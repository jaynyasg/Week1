# Deployment — Clinical Co-Pilot on Fly.io

This document is the decision record and runbook for PR-02. It captures *why* Fly.io was chosen, *how* the deploy is structured, and *what* to do when something breaks.

## Decision: Fly.io

**Chosen over:** Railway, AWS EC2, Render, Heroku.

### Why Fly

| Criterion | Fly.io | Railway | AWS EC2 |
|---|---|---|---|
| Multi-container Docker support | First-class (one app per service) | Yes (Nixpacks or Dockerfile) | Manual (you install Docker) |
| Persistent volumes | Built-in (`fly volumes`) | Built-in | EBS — manual setup |
| Free HTTPS | Yes (`*.fly.dev`) | Yes | ACM + ALB ($) |
| Private network between apps | 6PN (`.internal` DNS), zero config | Same-project network | VPC — manual setup |
| Cold-start behavior on persistent services | Stays warm by default (`auto_stop_machines = "off"`) | Cold-starts after idle | N/A (always-on EC2) |
| Cost for a 2-app, 1GB-each, always-on stack | ~$10/mo | ~$10/mo | ~$30/mo (t3.small × 2 + EBS + ALB) |

The decisive factors were (1) the `.internal` private network, which lets MariaDB stay completely off the public internet with zero config, and (2) `auto_stop_machines = "off"`, which avoids the cold-start penalty that would break OpenEMR sessions on Railway's default plan.

### Why not Railway

Railway is genuinely close. The deciding edge case: Railway's persistent-service cold-start can take 10–30 seconds, and OpenEMR's PHP session handling does not gracefully resume after a stopped MariaDB. Fly's always-on default avoids this entire failure mode.

### Why not AWS EC2

AWS gives more control but adds a security-group surface, a load-balancer config, an EBS volume lifecycle, and an ACM certificate workflow. None of that is wrong, but it triples the deploy time for an MVP and adds three places to misconfigure PHI exposure. AWS is the right answer when the project needs VPC-private subnets, IAM-driven service-to-service auth, or HIPAA BAA — none of which the MVP requires.

## Architecture

Two Fly apps in one organization, connected over Fly's private 6PN network:

| App | Image | Volume | Public? | Purpose |
|---|---|---|---|---|
| `clinical-copilot` | `openemr/openemr:7.0.2` | `openemr_sites` (3 GB) | Yes (HTTPS) | OpenEMR PHP/Apache app |
| `clinical-copilot-db` | `mariadb:10.11` | `mariadb_data` (3 GB) | **No** | MariaDB, reachable only via `.internal` |

The OpenEMR app talks to the database via `clinical-copilot-db.internal:3306`. There is no public TCP path to MariaDB — `test_mysql_port_not_exposed` in `tests/integration/test_deployment.py` enforces this.

## Secrets

All secrets live in Fly's secret store, not in any committed file. The auto-generated values are:

| Secret | App | Generated by |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | db | `openssl rand -hex 24` |
| `MYSQL_PASSWORD` | db | `openssl rand -hex 24` |
| `MYSQL_ROOT_PASS` | openemr | copied from db's `MYSQL_ROOT_PASSWORD` |
| `MYSQL_PASS` | openemr | copied from db's `MYSQL_PASSWORD` |
| `OE_PASS` | openemr | `openssl rand -hex 16` (initial admin password — **save this**) |

`scripts/deploy_fly.sh` generates these on first run and prints `OE_PASS` once. There is no way to recover it later — set a known value before running the script if you need to.

## Runbook

### First deploy

```bash
bash scripts/deploy_fly.sh
```

The script is idempotent. First run: ~5–10 min (image pulls, volume creation, OpenEMR auto-installer). Subsequent runs: ~2 min.

### Tail logs

```bash
fly logs --app clinical-copilot          # OpenEMR
fly logs --app clinical-copilot-db       # MariaDB
```

### SSH into a container

```bash
fly ssh console --app clinical-copilot
fly ssh console --app clinical-copilot-db
```

### Inspect MariaDB directly

```bash
fly ssh console --app clinical-copilot-db -C \
  'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" openemr -e "SHOW TABLES;"'
```

### Reset everything (DESTRUCTIVE — wipes all PHI on the volumes)

```bash
fly apps destroy clinical-copilot
fly apps destroy clinical-copilot-db
```

## Known limitations

1. **Single region (iad).** Multi-region requires a volume per region and a strategy for MariaDB replication — out of scope for MVP. Document explicitly in `ARCHITECTURE.md`.
2. **Volumes are not snapshotted automatically.** Before going to anything resembling real PHI, add `fly volumes snapshots create` to a daily cron. For demo data this is acceptable.
3. **OpenEMR auto-installer runs on first boot only.** It writes `sqlconf.php` to the `openemr_sites` volume; subsequent boots skip the installer. If you destroy the volume but not the app, the install loop never re-runs and the app fails. Solution: destroy both, or `fly volumes destroy openemr_sites` and re-deploy.
4. **No custom domain configured.** The deploy uses `clinical-copilot.fly.dev`. To add `clinicalcopilot.example.com`, run `fly certs add clinicalcopilot.example.com` after pointing DNS.
5. **HIPAA BAA is not in place.** Per the Gauntlet rules, this deployment carries demo data only. Do not put real PHI on this stack.

## Verifying the deploy

```bash
DEPLOYED_URL=https://clinical-copilot.fly.dev pytest tests/integration/test_deployment.py -v
```

All seven tests must pass before submission. The tests cover:

1. Root URL responds 200
2. All traffic is HTTPS
3. The OpenEMR login page is served
4. The FHIR R4 metadata endpoint responds
5. Unauthenticated `/fhir/Patient` returns 401/403 (no PHI leak)
6. MariaDB port 3306 is not publicly reachable
7. Server response headers don't leak PHP/Apache versions (informational)

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Health check fails for 5+ min on first deploy | Auto-installer still running; schema creation can take 3–5 min on shared CPU | Wait. Watch `fly logs --app clinical-copilot`. |
| `Connection refused` to MariaDB from OpenEMR | `clinical-copilot-db` not deployed yet, or in a different Fly org | `fly status --app clinical-copilot-db`; confirm both apps in the same org |
| `sites/default/sqlconf.php exists` error after volume destroy | Stale volume content from a prior install | `fly volumes destroy openemr_sites` then re-run deploy |
| Login page loads but credentials rejected | `OE_PASS` not set, or installer ran with different value than current secret | Reset: `fly ssh console --app clinical-copilot -C 'cat /var/www/localhost/htdocs/openemr/sites/default/sqlconf.php' \| grep pass` |
| `test_mysql_port_not_exposed` fails | Someone added a `[[services]]` or `[http_service]` block to `fly.db.toml` | Remove it. MariaDB must never have a public service block. |
